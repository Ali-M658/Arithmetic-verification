## 4. Manuscript risks that remain

Ranked by what a referee would actually catch.

### 4.1 Blocking until push

The four public-availability claims above. A referee who follows the URL in the Data-availability
statement today finds code that verifies none of the paper. This is the single highest-severity
item in the whole review, and it is not fixable by writing more code — only by publishing it.

### 4.2 Needs a sentence in the manuscript

**`DE-02` — the counting convention is unstated.** The manuscript defines `N(S)` as "the number of
two-coefficient degeneracies" without saying whether a degeneracy is a *pair* or an *equivalence
class*. Both are computed here and they differ. Table 1's printed values follow the pairs
convention. First divergence is at **S = 136**, not at S = 200 as the original audit estimated from
checkpoint data alone. See [convention-note.md](convention-note.md) for the one-sentence fix.

### 4.3 Quoted results, correctly attributed but not independently verified

Four rows — `CV-01`, `HC-08`, `HC-20`, `HC-21` — are the DGGW/Schueth/Uçar heat-expansion inputs.
The harness verifies everything *derived from* them (notably that eq. (5) follows symbolically from
eq. (4), and that eq:a0conv agrees with the `(S₁+R−2)/12` form on every triad with `S₁ ≤ 200`), but
the expansions themselves are external and should stay cited, not re-derived. This matches the
manuscript's own "Load-bearing only" position in §1.4(c). **No action needed** — recorded so the
boundary is explicit.

### 4.4 Open by design

`DE-26`, `DE-27`, `DE-28` are the birthday heuristic and Conjecture 5.3, which the manuscript
already presents as non-rigorous and open. `DE-30` and `DE-31` are the `n`-cone remarks: `DE-31`
(`K ≤ n` for general `n`) is *stated but not proved in the manuscript*, so there is nothing to
reproduce. `code/orbifold_enum.py` is built for general `n` and exercised at `n = 3, 4, 5`, so the
machinery for a future `n = 4` witness search is in place, but no claim rests on it today.

## 6. Integrity verification

The requirement was that a broken check must propagate to a nonzero exit. Verified by deliberately
falsifying the area-convention assertion in stage 1 and running the suite:

```
=== BROKE the area-convention assertion (stage 1) ===
=== run_all.sh EXIT CODE = 1   (requirement: nonzero) ===

summary
  FAIL(exit 1) 1. enumerator self-test
  PASS   2. displayed identities
  PASS   3. degeneracy enumeration
  PASS   4. LaTeX table generation
  PASS   5. three-way cross-check
  PASS   6. claim-ledger coverage

FAIL -- one or more stages failed.
```

The file was then restored and confirmed byte-identical by SHA-256. Note that the suite runs **all**
stages even after one fails, so a single run reports every problem rather than only the first.

A second break test falsified the `S = 600` cumulative checkpoint in `enumerate_degeneracies.py`;
that module exited `1` and named both mismatched values (`cum_pairs = 3067, expected 9999`).

Other integrity properties, by construction:

- **No hardcoded fallback data.** Where the superseded upstream script printed canned rows when its
  search came up empty, `make_table.py` and `enumerate_degeneracies.py` raise instead.
- **No unconditional success.** There are 0 `assert` statements in the four upstream scripts at
  HEAD; the harness runs 27 tagged check groups plus 11 enumerator self-tests, all assert-based.
- **Exact arithmetic.** Integers and `Fraction` throughout. Floating point appears in exactly one
  function, `power_law_exponent`, marked with a banner comment, used only for the empirical growth
  exponent that supports a conjecture. Even the decimal columns of the LaTeX tables are rendered
  from exact `Fraction` values by integer arithmetic.
